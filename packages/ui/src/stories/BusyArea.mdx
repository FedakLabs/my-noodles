# BusyArea

One wrapper for “this region is loading.” Configure **`dim`** (visual) and **`scrim`** (click shield) independently.

## Two mechanisms

```
┌─────────────────────────────┐
│  SCRIM (invisible shield)   │  ← captures clicks; no extra tint
├─────────────────────────────┤
│  CONTENT (dimmed)           │  ← opacity fade on the wrapper
│  product tiles, text…       │
└─────────────────────────────┘
```

### Dim

- **What it is:** The content itself is faded (`opacity: 0.65` on the wrapper).
- **In code:** internal `BusyDim`, prop `dim`, token `BUSY_CONTENT_DIM_OPACITY`.
- **Effect:** Text and images look washed out. **Clicks still reach the content** when `scrim={false}`.

### Scrim

- **What it is:** An invisible layer on top — **no background tint**.
- **In code:** internal `BusyScrim`, prop `scrim`.
- **Effect:** Blocks pointer events on the region (`aria-busy`). Pair with `dim` for the visual “paused” read on catalog grid and filters.

### Why both together?

On the catalog grid:

- **Dim** — content looks inactive (soft 750ms fade)
- **Scrim** — tiles and links cannot be clicked while refetching

| Prop         | What it does              | When to use                                 |
| ------------ | ------------------------- | ------------------------------------------- |
| **`dim`**    | Fades wrapped children    | Toolbar status slice; catalog grid          |
| **`scrim`**  | Invisible click shield    | Catalog grid, filter panel — default `true` |
| **`show`**   | Gate dim + scrim          | Empty grid — timing runs, chrome hidden     |
| **`timing`** | Shared `useBusyAreaState` | One hook per screen, multiple BusyAreas     |

**Default:** `dim` and `scrim` are both `true`.

### Presets (apps/web)

| Screen         | Props                                                      |
| -------------- | ---------------------------------------------------------- |
| Toolbar status | `dim scrim={false}` + shared `timing`                      |
| Product grid   | `timing` + `show={isRefetching}`                           |
| Filter panel   | `busy` + `show={isRefetching}`                             |
| Navigation     | `StableLinearProgress` below app bar — no BusyArea (below) |

## Timing: `useBusyAreaState(busy)`

| Field / token                       | Meaning                                            |
| ----------------------------------- | -------------------------------------------------- |
| `mounted`                           | Scrim shield in DOM through exit                   |
| `active`                            | Dim visually on — pass to `show` or use as default |
| `BUSY_CHROME_TRANSITION_MS` (750ms) | Default dim fade                                   |
| `BUSY_CHROME_TRANSITION_EASING`     | Symmetric ease-in-out for dim                      |
| `SMOOTH_TRANSITION_MS` (450ms)      | Progress bars — override via `timingOptions`       |

Share one hook across toolbar + grid:

```tsx
const timing = useBusyAreaState(isRefetching);

<BusyArea timing={timing} dim scrim={false} label="…">{status}</BusyArea>
<BusyArea timing={timing} show={showGrid} label="…">{grid}</BusyArea>
```

## Global navigation (apps/web)

Route changes use **`StableLinearProgress`** fixed below the app header — not BusyArea. The bar appears immediately on link click and fades out when the route settles.
